![Python](https://img.shields.io/badge/Python-3.10%2B-blue?logo=python&logoColor=white)

Пайплайн для автоматической классификации отзывов с помощью LLM. Скрипт читает CSV с отзывами, отправляет их батчами в языковую модель через OpenRouter API, получает тональность, тему и краткое содержание для каждого отзыва — и сохраняет результат в новый CSV.

## Как это работает

```
data/input_reviews.csv
         │
         ▼
  Читаем pandas DataFrame
         │
         ▼
  Делим на батчи по 5 отзывов
         │
    ┌────┴────┐
    │  Батч   │  ──► Формируем промпт со всеми 5 отзывами
    └────┬────┘
         │
         ▼
  POST /chat/completions (OpenRouter API)
         │
         ▼
  Извлекаем JSON-массив из ответа модели
         │
    ┌────┴─────────────┐
    │ Успех            │ Ошибка / 429 / плохой JSON
    ▼                  ▼
  Добавляем        Retry (до 3 раз)
  результаты       └──► Если все попытки провалились:
  в список              помечаем батч как "ошибка"
         │
         ▼ (все батчи обработаны)
  data/output_reviews.csv
```

## Возможности

- **Батчевая обработка** — 5 отзывов за один запрос к API, экономит токены и ускоряет обработку
- **Автоматический retry** — при rate limit (HTTP 429) ждёт 15 секунд и повторяет попытку; максимум 3 попытки на батч
- **Устойчивый парсинг JSON** — ищет `[...]` в ответе модели, отсекая любой лишний текст вокруг массива
- **Фолбэк при ошибке** — если батч не удалось обработать после всех попыток, записи всё равно попадают в CSV с пометкой `"ошибка"`, а не теряются
- **Поддержка русского языка** — промпт и ответ на русском, CSV сохраняется в UTF-8 с BOM (корректно открывается в Excel)
- **Прогресс в консоли** — при каждом батче выводится диапазон строк и статус

## Формат данных

### Входной файл — `data/input_reviews.csv`

Разделитель: `;`, кодировка: `UTF-8`

| Столбец | Описание |
|---|---|
| `review_id` | Уникальный ID отзыва |
| `user_id` | ID пользователя |
| `username` | Имя пользователя |
| `product_id` | ID товара |
| `product_name` | Название товара |
| `review_date` | Дата отзыва |
| `city` | Город покупателя |
| `is_verified_purchase` | Подтверждённая покупка |
| `likes_count` | Количество лайков |
| `rating` | Оценка (1–5) |
| `review_text` | Текст отзыва |

> Модель видит только `review_id`, `product_name`, `rating` и `review_text` — остальные поля в промпт не передаются.

### Выходной файл — `data/output_reviews.csv`

Разделитель: `;`, кодировка: `UTF-8-BOM`

| Столбец | Описание | Возможные значения |
|---|---|---|
| `review_id` | ID из входного файла | — |
| `sentiment` | Тональность | `положительный` / `отрицательный` / `нейтральный` / `ошибка` |
| `topic` | Тема отзыва | 1–2 слова |
| `summary` | Краткое содержание | до 10 слов |

## Переменные окружения

| Переменная | Обязательная | Описание | Пример |
|---|---|---|---|
| `API_KEY` | ✅ | API-ключ OpenRouter | `sk-or-v1-...` |
| `MODEL` | ✅ | Название модели | `openai/gpt-4o-mini` |
| `API_URL` | ✅ | URL иодели | `https://openrouter.ai/keys` |

Для задачи классификации отзывов достаточно лёгкой и дешёвой модели, например `openai/gpt-4o-mini` или `google/gemini-flash-1.5`.

## Особенности реализации

### Батчевая обработка

Отзывы отправляются группами по 5 штук в одном промпте. Это снижает количество API-запросов в 5 раз по сравнению с поштучной обработкой и сокращает общее время работы скрипта.

### Парсинг ответа модели

Модели иногда оборачивают JSON в Markdown-блоки или добавляют пояснительный текст до/после массива. Скрипт не полагается на то, что ответ будет чистым JSON — он ищет первый `[` и последний `]` в строке и парсит только эту часть:

```python
start = content.find('[')
end = content.rfind(']')
clean_json = content[start:end+1]
```

### Обработка ошибок

| Ситуация | Поведение |
|---|---|
| HTTP 429 (rate limit) | Пауза 15 сек, затем повтор (до 3 раз) |
| Другие ошибки API | Пауза 5 сек, повтор |
| Некорректный JSON | Пауза 5 сек, повтор |
| Все 3 попытки провалились | Записи батча помечаются `"ошибка"` и сохраняются |

Благодаря фолбэку итоговый файл всегда содержит столько же строк, сколько входной — ни одна запись не теряется.

### Кодировка

Входной файл читается как `utf-8-sig` (снимает BOM при чтении). Выходной сохраняется тоже в `utf-8-sig`, что обеспечивает корректное отображение кириллицы при открытии файла в Microsoft Excel напрямую.
